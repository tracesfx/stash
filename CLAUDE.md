# Stash — project guide for Claude

Windows-only, ultra-fast inspiration capture tray app. Requirements live in `SPEC.md` (source of truth; update it when decisions change).

## Non-negotiables
- Capture = hotkey + drag, saved with no further input. Never add a required dialog, prompt, or naming step.
- Idle footprint is a feature: no polling, no replay buffer, no visible windows when idle. Webview windows are created on demand and destroyed on close, with one exception the user approved (2026-11-22): Settings > Keep gallery ready (default on) keeps the gallery loaded but hidden, so it opens instantly. A hidden window must never take focus or show itself.
- One shared library folder of plain files + JSON sidecars (SPEC §5). Never require a DB to read the library.
- UI is never on the critical save path; saving happens in Rust.
- Feedback is a non-focus-stealing toast. Never steal focus from the user's app.
- No network calls, accounts, or telemetry.

## Stack & layout (planned)
Tauri v2 · Rust core in `src-tauri/` · web UI in `src/` (TypeScript, minimal deps).
Rust modules: `capture/` (screen, clipboard, selection), `library/` (ids, sidecars, index, trash), `hotkeys.rs`, `tray.rs`, `overlay/`, `config.rs`.

## Conventions
- Rust: `anyhow` for app errors, `tracing` logs to `%APPDATA%\Stash\logs`. No `unwrap()` on I/O paths.
- Atomic writes: temp file + rename; image first, sidecar last.
- Capture code must be correct on multi-monitor and mixed per-monitor DPI.
- When touching capture/overlay, measure against SPEC §9 and report the numbers.
- Keep dependencies small; justify each new crate in the commit message.
- Go milestone by milestone (SPEC §10); don't build M3+ features during M1.

## Update (perf pass: instant gallery, frame pacing, frame-rate cap)
- Keep gallery ready (config `keep_gallery_ready`, Settings > General > System, advanced): gallery.rs `prewarm` builds `gallery.html?warm=1` hidden 2 s after startup with `.focused(!warm)` (a new tao window takes the foreground even while invisible). Close = `begin_hide` -> page blanks -> `gallery_hide_ready` -> hide + WebView2 MemoryUsageTargetLevel LOW -> page reloads itself hidden. Open on the hidden window emits `gallery-show`; gallery.ts `showWarm`/`arm`/`disarm` keep the entrance prepared and paused while hidden; `gallery_warm_paint` paints once off-screen. Turning the setting off calls `release`.
- `show_if_not_ready` asks whether *this* open was revealed (`REVEALS` per label), never `is_visible()`: a gallery closed within the 1.5 s wait must stay closed, and test-mode windows shown with a raw ShowWindow look hidden to tao.
- Video cards show a poster (poster.rs, Media Foundation first non-black frame); the `<video>` is created on hover. Scan cache (`SCAN_CACHE`, `LIB_FP`; `gallery_list(since)` returns `{fp, items|null}`). Virtualization: only tiles within ~1.5 screens are attached (`virtualize`), so code must not assume every card is in the DOM.
- Native frame pacing: `gfx::FramePacer` (vblank-aligned via DwmGetCompositionTimingInfo + high-resolution waitable timer, sends WM_TIMER) replaces SetTimer in wheel.rs, radial.rs, toast.rs and note.rs (note: only while opening). WM_TIMER handlers must repaint only when something changed (radial `dirty`, toast `still`): ticks come at up to 240 Hz.
- Animation frame-rate cap: `appearance.anim_fps` (0 = Auto, else 15-240; Settings > Appearance > Motion > Frame rate). Native: `gfx::set_fps_cap` (startup + `theme::apply`). Web: src/fps.ts (imported by theme.ts) pauses running Web Animations and steps them at the cap, only when the cap is below the measured refresh rate; it patches Animation.prototype.play/pause so page-paused animations (the armed entrance) are left alone. JS-driven motion (scrolling, cursor glow, burn) is not capped.
- Perf tooling: src/perf.ts marks + `STASH_PERF=1` (frame recorder, long-animation-frame observer, `perf pacer:` tick stats in the log). Test aid `STASH_TEST_NOACTIVATE=1` (reveal shows topmost without focus). Scripts in perf-tools/ (gitignored, local; HANDOFF.md explains them; t.ps1 drives an isolated com.stash.perftest instance). Headless gallery regression check: mock/check.cjs + mockserve.cjs (`?n=3000` big library, `?fps=30`), kept in perf-tools/mock. Promo footage work lives in footage/ (gitignored; RESUME.md).
- Glass fade: `backdrop::fade_in` (composition Opacity animation, 380 ms) runs in `reveal` on the main thread *before* the window shows; `backdrop::clear` after hiding, so a reused window never shows a frame of full-strength glass. `gallery_hide_ready` returns true whenever the window ended up hidden (also when the 300 ms fallback in `begin_hide` beat a busy page); the page treats false as "reopened" and calls `window_ready` itself. `gallery_warm_ready` is also true when the window is natively visible (Ctrl+R / F5 reload the `?warm=1` page in place).
- Live regression pass: perf-tools/regress.cjs (16 checks: open/close cycles, quick close, reopen during hide, reload, capture while hidden, settings while hidden, 10k library switch + busy-close race, keep-ready off/on, log + page errors). Test-mode windows (topmost, never activated) get activated + minimized by the shell ~2 s after showing; production windows are activated, so ignore that in tests.
